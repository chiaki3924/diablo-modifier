## 2. Bug 1：改储物箱金币清空物品

### 2.1 根因（已复现）

原 `d1save.StashFile.save()` 在重建 MPQ 时从 header `offset 12`（format_version=0）
读扇区位移，正确字段是 `offset 14`（sector_size_shift=3）。于是它按 **512 字节**
扇区写偏移表，但块 flags 仍保留 `0x80000100`（EXISTS|IMPLODE）。游戏按 **4096**
字节扇区读表，第 0 扇区 `span=512` ≠ `expect=4096`，把原始数据当 PKWARE 压缩流
解压 → 失败 → `LoadStash()` 放弃 → 箱子为空 → 玩家开箱/退出时写回空箱。

实测原修改器保存后的块表首项 = **300** = `(37448/512+1)*4`；正确 4096 扇区应为
**44**。原修改器自己的读取器也读不回（`PkwareError: 字典大小非法`）。

### 2.2 修法

按 mpqfs 写入器的“压缩无收益”分支，写**未压缩**块：

```
flags = 0x80000000              # EXISTS，无 IMPLODE/COMPRESS
block_data = codec_encode(payload)  # 无扇区偏移表
compressed_size = uncompressed_size = len(block_data)
```

重加密块表、更新 `header.archive_size`、16 字节对齐追加、哈希表不动。
备用写法 `write_mode="implode_raw"`（4096 扇区表 + 原样扇区 + IMPLODE）已验证
可被原 `d1save` 读取，作为逃生门。

### 2.3 测试（`work\tests\test_stash.py`，14 项全过）

- 改 gold 313108→196607：文件 90346→103096，96 条记录 SHA256 完全相同，
  页/格完全相同，payload 仅 offset 1..3 变化；块

## 3. Bug 2：自由生成合规词条装备

### 3.1 关键设计：不伪造字段，而是搜索种子

1.5.5 中魔法物品的显示名字不是直接读存档 `_iIName`，而是 `Item::getName()`
→ `GetTranslatedItemNameMagical()` 用 **`_iSeed + _iCreateInfo` 重放 RNG**
重新算出来的。因此“直接改 PrePower/VAdd/名字”会在游戏里显示成另一套名字。

本工具的做法：
1. 用 1.5.5 源码表（`AllItemsList`/`ItemPrefixes`/`ItemSuffixes`/`UniqueItems`）
   构建底材/词缀/暗金数据；
2. 按游戏源码逐行移植 `GetItemAttrs`、`GetItemBLevel`、`CheckUnique`、
   `GetItemPowerPrefixAndSuffix`、`SaveItemPower`、`ItemRndDur`、`SetupAllItems`；
3. 用户选定前缀/后缀后，遍历 seed，快速模拟“选择阶段”，找到自然 roll 出
   该组合的 seed；再用完整流程生成 368 字节记录；
4. `validate()` 再用记录里的 seed/createInfo 重放，核对名字/词缀/数值/耐久。

因此生成物与游戏自己掉落/生成的物品一致，不是“改字段”的假货。

### 3.2 数据/规则

- 底材：1.5.5 `AllItemsList` 全表；`available` 按 `IsItemAvailable()`。
  同名条目（如 idx=1 starter Short Sword 20/50 与 idx=119 droppable 24/120）
  保留并标记，默认用 droppable 版本。
- 词缀：前缀 86 / 后缀 98；按 `AffixItemType`、`PLMinLvl`、`PLDouble`、
  `PLGOE`、`PLOk`、Staff 排除规则过滤。
- 暗金：90 条，按 `UIMinLvl`/底材匹配；支持指定 uid。
- 字体宽度：从 `devilutionx.mpq` 提取 12px 字宽表，复现
  `StringInPanel(<254)` 的“长名→短名”回退。

## 6. 遗留风险

1. 游戏内只测了 1.5.5 非 Hellfire；Hellfire 372B 物品格式未适配。
2. 未压缩 MPQ 块是 mpqfs 的合法冷路径（游戏自己的 writer 也会这么写），
   但真实存档里原先都是 IMPLODE；若游戏内异常，可切 `implode_raw`。
3. 自选词条搜索对某些低等级词缀/高 ilvl 组合不存在（游戏规则限制），
   UI 会提示并列出可用词条。
4. 修改器写盘会追加新块（文件每次增大 ~37KB），游戏下次保存会压缩重写；
   不影响使用。
5. 生成物建议一次 ≤10 件，进游戏确认后再继续。

## 10. Round 5（2026-11-12）：v2.4.0 丢地「无效的数据包」/ 法术 22 条 / pMemSpells 位图

> 详细证据见 `work\docs\verify5_report.md`、`work\docs\ROUND5_BRIEF.md`；
> 本节只摘结论。真实存档全程 **0 写入**（开始/结束快照逐字节一致）。

### 10.1 用户报的两个问题

1. 生成的装备丢到地上会提示「无效的数据包」，然后消失；正常装备可以丢地上再捡起来。
2. 角色界面的法术：混进了地狱火版本的法术；还有单人学不了的
   「治疗他人 / 复活」，以及游戏设定学不了的「鉴定 / 夜视 / 天启」和三个职业自带技能；
   而且单独学某个法术后，其他法术等级会被清零。

### 10.2 根因

**丢地失败**：游戏走 `msg.cpp` 的 `IsPItemValid()` →
`IsCreationFlagComboValid()` + `IsDungeonItemValid()`。非 Hellfire 的
`IsDungeonItemValid` 取 `level = iCreateInfo & CF_LEVEL`，先匹配怪物等级，
匹配不上就只允许 `level <= (16-1)*2 = 30`，**ilvl>30 一律非法**。
校验失败即 `EventFailedPacket()`（中文「无效的数据包」）并 `return false`，
物品不落地 —— 表现就是“消失”。工具旧版把 ilvl 默认设为角色等级
（34/43/49），写进 `iCreateInfo`，所以 31~50 的生成物丢地必失败；
暗金页 `ilvl = max(20, unique.min_level)` 同理。

**法术异常**：`pMemSpells` 是 64 位记忆位图，游戏按 `1 << (spell_id - 1)`
判“已学”（`objects.cpp` 的循环从 spell=1 对应 bit 0 起）。
旧代码写成 `1 << spell_id`，整体错一位：设置 12 号会点亮 13 号的位、
自己那一位没亮，于是出现“学了 A、其它法术等级异常/清零”。
另外旧列表把 Hellfire 37~46、Nova/天启、鉴定/夜视/复活/治疗他人、
职业自带能力都算了进来。

### 10.3 修法

- `d1itemgen`：新增 `MAX_DROP_ILVL = 30`、`droppable_level_ok(ilvl)`；
  `generate(..., droppable=False)` / `check_combination(..., droppable=False)`，
  `droppable=True` 且 ilvl>30 → `ItemGenError(code="drop_ilvl")`，中文提示
  “ilvl N 的物品丢地上会被游戏判定为非法数据包并消失；请把 ilvl 降到 30
  或以下，或取消‘保证可丢地上’”，建议含“把 ilvl 降到 30”。
- adapter / UI：装备生成页与暗金图鉴固定栏各加「可丢地上（≤30）」勾选框，
  **默认勾选**；勾选时 ilvl 范围 1~30（载入 34 级角色也会钳到 30），
  取消勾选恢复 1~50 并红字提示“只能放储物箱”；暗金 `min_level>30` 时
  自动取消勾选并提示。
- `d1tables`：新增 `D1_LAST_SPELL=36`、`spell_bitmask(id)=1<<(id-1)`、
  `learnable_spells()`（单人 22 条 / 多人 23 条）。

### 12.1 问题 1：ilvl 31~34 走「暗金怪掉落路线」

**根因**：丢地走 `msg.cpp:IsPItemValid()`。非 Hellfire 的判定顺序是
`IsCreationFlagComboValid()` → `CF_TOWN ? IsTownItemValid` → `(ci & CF_USEFUL) == CF_UPER15 ?
IsUniqueMonsterItemValid` → `IsDungeonItemValid`。普通地牢物品只认 `level <= 30`，所以旧版把
ilvl 直接写进 `iCreateInfo` 后，31~50 丢地上必然 `EventFailedPacket()`（「无效的数据包」）。

但暗金怪掉落的物品带 `CF_UPER15`，记录写怪物等级（`SpawnItem`，`items.cpp:3266`），
词缀等级却按 `iblvl = lvl + 4` 计算（`SetupAllItems`，`items.cpp:1529`）。因此 **ilvl 31~34
在游戏里天然存在**，只是旧版没走这条路。

**修法**（`work\lib\d1itemgen.py`）：

| 虚拟 ilvl | 记录 level | flags | uper | onlygood | 词缀窗口 |
|---|---|---|---|---|---|
| 0..30 | ilvl | 0 | 0 | 原样 | `[min(ilvl//2,25), ilvl]` |
| 31..34 | ilvl−4（27..30） | `CF_UPER15\|CF_ONLYGOOD` = `0x00C0` | 15 | True | `[min(ilvl//2,25), ilvl]`（= 记录等级+4） |
| 35..50 | 不允许 `droppable=True` | — | — | — | 仅储物箱 |

* 27..30 全部是真实暗金怪等级，`IsUniqueMonsterItemValid()` 通过；暗金再多写 `CF_UNIQUE`
  （`0x02DE`）。`record_droppable()` 对 `0x00DE`/`0x02DE` 返回 True，对裸 ilvl 34 返回 False。
* `_generate()` / `check_combination()` 统一走 `drop_plan()`：`record_ilvl` 写记录、`uper=15`
  传给重放（15% 暗金概率），再按用户选的品质过滤种子；`display_ilvl` 保留 31~34 用于文案。
* 31~34 唯一新解锁的词缀是前缀 **Emerald**（index 66，`IPL_ALLRES` 41~50，min_level 31），
  作为回归锚点：`Emerald@34` 生成全抗 50 且 `validate()==[]`，`Emerald@30` 报 `level_window`。
* 副作用：`CF_ONLYGOOD` 会排除 `PLOk == false` 的诅咒词缀，31~34 的生成物不带诅咒。

**顺带修掉一个真 bug**：`record_droppable()` 第一版把 `CF_TOWN` 写成 `flags == CF_TOWN`（要求
四个 town flag 同时存在），又把 `CF_USEFUL` 双位一律判非法，导致 Adria 的 `0x400F`
（`CF_HEALER|15`）、女巫的 `0x2010`（`CF_WITCH|16`）等正常城镇物品被误报成「丢地上会无效」。
按源码改成「town flag 恰好一位」+「`CF_USEFUL` 仅在还有其它 flag 时非法」后，储物箱
「检查异常物品」对 96 件干净物品的误报从 5 条降到 0 条。

### 12.2 问题 2：一个词缀两条属性（国王 = 伤害 + 命中）

`SaveItemPower()`（`items.cpp:746`）里 `IPL_TOHIT_DAMP` / `IPL_TOHIT_DAMP_CURSE` /
`IPL_DOPPELGANGER` **先** `r = RndPL(p1, p2)` 加到伤害，**再**单独一次 `CalculateToHitBonus()`。
共 12 条词缀（Clumsy/Dull/Sharp/Fine/Warrior's/Soldier's/Lord's/Knight's/Master's/Champion's/
King's/Doppelganger's），King's = 伤害 151~175 + 命中 76~100。

**修法**：

* core 新增 `affix_value_slots()`（返回 `[{"key","label","range"}, ...]`，固定效果返回 `[]`）、
  `_normalize_value_target()`（int / `"151/93"` / list / tuple；未填槽 `None`）、
  `_consume_power_rolls()`、`_slot_value_ok()` / `_format_value_failure()`（错误点名「命中」）。
* 兼容旧 API：单个 int 只钉住槽 0（伤害），命中仍然随机。
* UI：每个词缀最多两个带标签的输入框（`伤害 151~175` / `命中 76~100`），单槽隐藏第二个，
  固定效果禁用并显示「固定效果」；`_params_dict()` 单槽发 int、双槽发 `[v0, v1]`。
* 结果区用 `GenResult.prefix_values` + `d1zh.power_value(..., tohit=)` 显示
  「伤害 +151%，命中 +93%」两个真实值（只填一个时另一个显示随机到的实际值）。

**同时修掉诅咒词缀的符号 bug**：`CalculateToHitBonus(-50) == -RndPL(6,10)`、`(-25) == -RndPL(1,5)`。
旧实现按正数返回，Clumsy 会写成 `PLToHit=+6`，与游戏重算不一致。修法：先掷正幅度再取负
（不能直接 `RndPL(-hi,-lo)`，RNG 次数/映射会错位）。验证：Clumsy → `PLDam=-50, PLToHit=-8`，
`validate()==[]` 且重放逐字节一致。

### 12.3 问题 3：储物箱列表中文名

* `d1stash_adapter` 新增 `record_name_cn(rec)` / `record_label_cn(rec)`：
  `d1itemgen.replay_item()` 重放拿到底材/前缀/后缀/暗金/法术，再用 `d1zh` 拼中文名
  （暗金名、`前缀 + 底材 + of 后缀`、`法术书：传送术`、`火球术长杖`）。
  法术编号取记录 offset 224（重放对法术书可能取到别的法术）；按 `(saved_idx, seed, createInfo)`
  缓存；任何异常退回「底材中文名（魔法/暗金）」或英文名，不抛异常。
* `ui_stash` 的名称列、`scan_issues` 横幅/列表、删除确认、「异常物品」对话框全部改用
  `record_label_cn`，格式 `中文名（English）`（例 `阿凯尼的荣耀（Arkaine's Valor）`）。
* 实测：96 件 96 个中文名；一次导入 243ms + 96 件 16ms；首次 `_fill_list` 265~287ms。
